# CP candidate calling lists

Available in the web navigation and mobile More > CP calling lists.

| Role | Access |
| --- | --- |
| MD | All lists, uploads, assignments, previews, downloads and CP creation |
| MIS | Upload and manage their own lists; assign any active RM; preview/download their own uploads |
| RM | Preview/download only lists currently assigned to them; create CPs from their assigned candidate rows |
| Other roles | No calling-list access, including CP Head and Admin Head |

Calling-list assignment is separate from employee reporting: MD -> CP Head -> RM -> CP; MIS reports separately to MD. Assignment does not add reporting or general employee visibility. Reassignment/unassignment removes the former RM's ability to obtain previews and new download links. Already downloaded copies cannot be recalled; issued S3 URLs expire after 60 seconds.

## Excel format and workflow

MD and MIS can choose **Download blank Excel template** from the upload panel on web or mobile. It contains only these headers: First name, Last name, Email, Mobile number, Address, City, Pincode, Notes. Enter one candidate per row starting at row 2, save as `.xlsx`, then upload. Phone and postal-code columns are formatted as text. State and district are chosen in the CP creation form. The template is generated by the API and does not require S3 access. Mobile uses the device save/share sheet.

Use a single unencrypted `.xlsx` worksheet with a unique nonempty header in each column of row 1. Legacy `.xls`, macros, external workbook links, more than 50 columns, more than 10,000 data rows, compressed files over 5 MB and declared archive expansion over 30 MB are rejected. Each cell is limited to 2,000 characters. Blank data rows are skipped; original Excel row numbers are preserved. The original bytes are kept in private S3 storage, while all columns and candidate values are stored for paginated, text-only previews. Formulas are not executed in the app.

Suggested headers: `First name`, `Last name`, `Email`, `Mobile number`, `Address`, `City`, `Pincode`. Optional `State ID` and `District ID` prefill geography; otherwise choose from active geography dropdowns at CP creation. `Name`, `Full name`, `Phone`, and `Email address` aliases are supported. Extra columns remain visible in the preview. Keep phone numbers as Excel text to preserve leading characters.

MIS/MD supplies a title, chooses a workbook and optionally assigns an active RM. Each assigned RM sees their files in their own panel. Preview shows all uploaded columns, 25 rows per page; download returns the original workbook. Lists use 20 records per page in the clients.

Only the assigned RM or MD can choose **Create CP** on a row. The reviewed form requires first name, last name, email, mobile number, address, state and district using the existing employee validation and geography checks. This creates an account under the assigned RM and sends its invitation; it does not bulk-import accounts during upload. MIS cannot convert candidate rows. A deterministic unique employee code (`CP-<candidate ID>`) makes retries safe, and converted rows show `CP created`. Existing candidate files are never rewritten. A list must be assigned before MD creates a CP. Invitation failure is reported separately; use Employees to resend.

Uploads expire after 15 minutes until completed. A per-list conversion lock prevents assignment changes or competing conversions during account creation. If the API process is terminated while converting, an operator must check the row's deterministic employee code, reconcile the row's employee link, then clear the list's `busy` flag before retrying. Existing employee uniqueness checks also apply.

## Storage configuration

`AWS_S3_CALLING_LIST_BUCKET` optionally selects a dedicated private bucket; fallback is `AWS_S3_BUCKET_NAME`, then `AWS_S3_PROFILE_BUCKET`. Existing region and credential settings are reused. Files use `calling-lists/<uploader ID>/<random UUID>.xlsx` with AES256 server-side encryption. Binary files are uploaded through the authenticated API, so no new browser-to-S3 PUT CORS rule is needed. Keep S3 public access blocked. Only short-lived authenticated download-link requests return S3 URLs. Preview data and links use `Cache-Control: private, no-store`.

Grant the backend identity `s3:PutObject`, `s3:GetObject`, and `s3:DeleteObject` for the bucket's `calling-lists/*` prefix. [CALLING_LIST_S3_POLICY.json](CALLING_LIST_S3_POLICY.json) is the exact resource-scoped policy for the currently configured `sunvika-media` bucket; adjust its resource if using a different bucket. Attach it using your AWS administration process and restart the API after configuration changes. No AWS permissions or bucket policies were changed during implementation.

A live synthetic workflow check on 10 November 2026 reached MongoDB but S3 rejected PutObject because the configured backend identity lacks access to this prefix. No S3 test file was created. Temporary calling-list and candidate database records were removed. Storage verification remains pending until IAM access is granted.

## API

All routes require a live authenticated employee/session. Access is enforced in the service for every preview, download, assignment and conversion, independent of client visibility. CP creation also requires `employees.create`.

- `GET /calling-lists?page=1&limit=20`: scoped list with total.
- `GET /calling-lists/template`: MD/MIS header-only Excel template as `{ fileName, contentType, base64 }`.
- `GET /calling-lists/managers`: minimal active RM directory for MD/MIS assignment only.
- `POST /calling-lists`: `{ title, fileName, size, assignedTo? }`; returns `_id` and upload expiry.
- `PUT /calling-lists/:listId/file`: XLSX bytes with the Excel MIME type or application/octet-stream; validates and stores the original file.
- `PATCH /calling-lists/:listId/assignment`: `{ assignedTo: "<active RM ID>" | null }`.
- `GET /calling-lists/:listId/preview?page=1&limit=25`: headers and candidate rows; row includes `_id`, `rowNumber`, `values`, and converted `employee` if present.
- `GET /calling-lists/:listId/download-url`: original file's 60-second S3 URL.
- `POST /calling-lists/:listId/candidates/:rowId/create-cp`: existing employee input with roleCode CP; server chooses the unique employee code and assigned RM manager. Returns employee ID and invitation delivery status.

Upload/assignment/conversion operations and sensitive preview/download JSON responses pass through the existing audit middleware. S3 object keys and bucket details are excluded from client list/preview responses.


### Permanently remove a candidate

`DELETE /api/v1/calling-lists/:listId/candidates/:rowId?confirm=true`

MD, the MIS uploader, and the currently assigned RM can permanently delete individual candidate records from a ready list. Both clients show a Delete button in the preview with an explicit confirmation popup. The row is removed from MongoDB, the stored candidate count is updated, and the preview refreshes (moving back a page when necessary). Missing confirmation is rejected. Candidates are matched by both row ID and list ID; other users receive no access.

Deletion and count changes use a database transaction and the same list lock as CP creation to prevent races with creation or reassignment. Failure releases the lock and rolls back the transaction. The original Excel workbook in S3 and any CP employee account already created from the row are retained; the confirmation explains this distinction. The existing audit middleware records the successful deletion.


### Calling-list progress counts

The list response includes `originalRowCount` (persisted on upload), `convertedCount`, `unconvertedCount`, and `deletedCount`. The web table and mobile cards show these before Preview. Counts refresh after creating a CP or deleting a row and when manually refreshing the list. There is no timed API polling.

Converted and unconverted totals are aggregated for all candidates in each authorized list, independently of preview pagination. Deleting a converted candidate increments `deletedConvertedCount` in the deletion transaction, so the list keeps credit for that conversion while retaining the CP account. Unconverted means candidates still available to call/convert; deleted candidates are excluded. Original upload totals never decrease. For older lists, the original total is recovered once from the unchanged Excel file in S3 and saved conditionally. If recovery is unavailable, the original total is shown as unavailable instead of an inaccurate replacement. Private S3 keys and bucket names are excluded from the response.

`totalCallingCount` is displayed as **Total calling** before Preview in both clients. It follows the requested formula: `deletedCount + convertedCount + interestedCount + followUpCount`. If the original count cannot be recovered, the metric is unavailable until it can be recovered.


### Candidate calling outcomes

`PATCH /api/v1/calling-lists/:listId/candidates/:rowId/status` accepts `callStatus` (`NOT_CALLED`, `INTERESTED`, `NEEDS_FOLLOWUP`, `NOT_INTERESTED`), an optional `callNote` (up to 1,000 characters), and `nextFollowUpAt` (ISO date/time, required only for needs-follow-up and otherwise null). Old rows with no status are treated as not called. Both clients display status near the start of the preview table and provide an Update status form; converted CP rows show Converted to CP and cannot be edited. Notes and scheduled local follow-up times appear in the row.

MD, the MIS uploader, and the assigned RM may update outcomes using the same list lock as conversion/deletion/reassignment. The API validates both list and row scope and records the updating employee and calling time. Clearing to Not called clears calling time. Leaving needs-follow-up clears the scheduled date. Existing audit middleware records successful status updates.

Summary and preview progress show `calledCount` (unique candidates marked with an outcome or converted, including called rows deleted after this feature), `interestedCount` and `followUpCount` (current unconverted candidates with these outcomes), and `notCalledCount` (current unconverted candidates with no calling outcome). Deleting a called row preserves its contribution in `deletedCalledCount` in the deletion transaction. These are candidate counts, not repeat call attempts. Historical deleted rows have no recoverable calling status and are not assumed called. Counts refresh after user actions or manual refresh; there is no polling. The separate Total calling metric retains the user's specified deleted-plus-converted-plus-interested-plus-follow-up formula.


### Upline list filters

Calling lists supports `rmId`, `dateFrom` and `dateTo` query filters for MD, MIS and CP Head. Both clients provide one searchable RM picker and Uploaded from/to dates. The date range uses the original list creation/upload date (`createdAt`) with inclusive IST calendar-day boundaries. Filters intersect visibility before list pagination and total counting. RM requests with upline filter parameters are rejected; their unfiltered view remains limited to assigned lists.

MD sees all ready lists. MIS retains its own-upload scope. CP Head can read only lists currently assigned to RMs within their hierarchy, including preview and download; CP Head cannot upload, assign, change calling outcomes, create CPs, or delete candidates. The web/mobile navigation includes the read-only calling-list view for CP Head. `GET /api/v1/calling-lists/filter-options` returns only currently assigned RM names from visible lists, including inactive assignees needed for historical lists. RMs cannot call this endpoint. Filter changes reset pagination and close the prior preview; Clear filters restores the permitted scope. No polling is added.
